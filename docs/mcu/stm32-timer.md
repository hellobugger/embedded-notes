# STM32 定时器：从时基到一堆「隐藏功能」的一篇讲透

> 一句话：**定时器是芯片里最全能的外设**——既能当「表」（计个数、算时间、出中断），又能当「波」（PWM 输出）、当「尺」（输入捕获测频率测脉宽）、当「芯」（给 ADC/DAC/别的定时器发触发）。要讲清楚的其实是四件事——**它有哪几类、各自能干什么**（基础/通用/高级）、**时基怎么配**（预分频 + 自动重装 + 时钟来源，先懂这个后面全通）、**三大基本用法怎么配**（定时中断/PWM/输入捕获）、**还有哪些别人不知道的功能**（编码器、级联、触发链、死区、DMA、刹车等）。本文以 F1/F4 的定时器为主，寄存器名与配置以 HAL 为准，时钟背景见 [stm32-clock-tree.md](stm32-clock-tree.md)。

## 一、定时器是什么、有几类

定时器 TIM（Timer）的本质是**一个带时钟的计数器**：给一个时钟，它数数，数到设定值就翻篇（更新事件），配合输出/输入通道就变成了 PWM 和测量工具。STM32 的定时器按能力和位宽分四档，**先分清代系再谈功能，这是全文最重要的前提**：

| 类别 | 位宽 | 定时中断 | PWM | 输入捕获 | 编码器/霍尔 | 死区互补 | DMA/触发链 |
| ---- | ---- | :------: | :--: | :------: | :---------: | :------: | :--------: |
| **基本定时器**（TIM6/7） | 16 位 | ✅ | ❌ | ❌ | ❌ | ❌ | ✅（只有 DMA 和触发） |
| **通用定时器**（TIM2/3/4/5） | F1 全 16 位；F4 的 TIM2/5 是 **32 位** | ✅ | ✅ | ✅ | ✅ | ❌ | ✅ |
| **高级定时器**（TIM1/8） | 16 位 | ✅ | ✅ | ✅ | ✅ | ✅（**死区+刹车**） | ✅ |
| 低功耗定时器（F4 的 LPTIM，另类） | 16 位 | ✅ | ❌ | ❌ | ❌ | ❌ | 唤醒用，独立时钟 |

- **基本定时器**：只会「数数出中断」，以及给 DAC 当触发源、自己用 DMA 搬数据。当不了 PWM。
- **通用定时器**：全家桶——PWM、输入捕获、编码器、级联，是日常用得最多的。
- **高级定时器**：通用定时器的一切 + **互补输出 + 死区 + 刹车（Break）**，专门给电机控制、半桥/全桥驱动设计的。**别用普通 PWM 去推半桥**，两个管子会瞬间直通烧板。
- **LPTIM**（F4 有）：挂 LSI/LSE 的极低功耗定时器，可以在低功耗模式下定时唤醒，属于低功耗专题，本文不展开。

一个芯片上有多路定时器，**每一路都是独立的**（各自时钟、各自计数、各自中断），互不干扰——这就是"定时器多"的意思，也是它功能多的原因。

## 二、定时器的时钟来源（先懂这个，后面算频率全靠它）

定时器不是自己会走，要有**时钟**驱动它数数。它的时钟挂在 **APB1 / APB2** 总线上，但有个关键规则：

!!! warning "定时器时钟 ≠ APB 时钟，跟预分频系数有关"
    - 当 **APB 预分频 = 1** 时，`定时器时钟 = APB 时钟`
    - 当 **APB 预分频 ≥ 2** 时，`定时器时钟 = APB 时钟 × 2`（硬件自动加倍）
    - F1 的 APB1 最多 36MHz、APB2 最多 72MHz，所以系统主频 72MHz 时：**TIM2/3/4/5（挂 APB1）跑 72MHz，TIM1/8（挂 APB2）也跑 72MHz**——APB1 预分频为 2，定时器就翻倍到 72MHz
    - CubeMX 时钟树里如果看见"定时器时钟 = 系统时钟"，就是这条规则在起作用。**别按 APB 时钟直接算，差一倍就全错了**

定时器内部还能**再分频**（见下节的 PSC），所以实际计数频率 = `定时器时钟 / (PSC+1)`。先记住这条链：**系统时钟 → 总线预分频 → 定时器时钟（可能 ×2）→ 定时器 PSC 分频 → 真正的计数频率**。

## 三、时基怎么配：PSC、ARR、CNT 三件套

这是定时器一切用法的地基。定时器有三件宝，都在一条数轴上：

| 寄存器 | 全称 | 作用 | 说明 |
| ------ | ---- | ---- | ---- |
| **CNT** | 计数器 | 现在数到哪了 | 会自己加/减，可读可写 |
| **PSC** | 预分频器 | 时钟先÷(PSC+1) 再给 CNT | **加 1 才起作用**，范围 0~65535 |
| **ARR** | 自动重装载值 | 数到 ARR 就归零/翻篇 | 16 位最大 65535，32 位定时器（TIM2/5）更大 |

**计数节奏**：`定时器时钟 / (PSC+1)` 是每秒数几下；CNT 从 0 数到 ARR 算一个周期。于是两个最常用的公式：

```text
定时中断频率（每多久翻篇一次） = 定时器时钟 / (PSC+1) / (ARR+1)
PWM 频率（输出方波的频率）     = 定时器时钟 / (PSC+1) / (ARR+1)
```

举例：`定时器时钟 = 72MHz`，想得到一个 **1kHz 的方波/1ms 定时中断**：

```text
72,000,000 / (PSC+1) / (ARR+1) = 1000
→ 取 PSC = 71（即 72 分频），则 72M/72 = 1MHz 计数频率
→ ARR = 999，则 1M/1000 = 1kHz ✅
```

!!! tip "算之前先把 PSC 拆到整数"
    习惯上**先把 PSC 拆成一个"干净的"分频**（让计数频率好除），再定 ARR。先拆 PSC 再定 ARR，顺序别反，否则很容易算出非整数频率。

### 中间那步：PSC 分频到底怎么理解

PSC 前面还有个隐含的"×2"可能（见第二节）。所以真正的链路是：

```text
系统时钟 → APB 预分频 → 定时器时钟（APB≥2 时自动 ×2） → PSC÷(PSC+1) → 计数时钟 → CNT 数到 ARR 翻篇
```

**PSC 的坑：改了 PSC 不立刻生效**。PSC 和 ARR 都有影子寄存器（shadow register）机制——你写进去的值要等**下一次更新事件（UIF）**才真正加载。刚初始化完想立刻用新值时，手动 `__HAL_TIM_SET_AUTORELOAD`/改 PSC 后可以主动产生一次更新事件让新值生效（HAL 的 `__HAL_TIM_SET_PRESCALER` 同理）。

### 更新事件（UIF）是什么

CNT 数到 ARR 翻篇的那一刻，会**产生更新事件**，同时置 UIF 标志。这个事件是三件事的触发器：

1. 触发**更新中断**（如果 NVIC 使能了）→ 你写的"定时到了该干嘛"的代码在这里跑
2. 让 ARR/PSC 的新值**生效**（影子寄存器装载）
3. 作为**触发信号**送给别人（DMA、别的定时器、ADC）——这就是后面触发链的基础

## 四、三大基本用法之一：定时中断

最简单也最常用的场景——每隔固定时间干一件事。CubeMX：选一个 TIM，设 `Prescaler`、`Counter Period(ARR)`，勾 `Update interrupt` 使能更新中断 → 生成。

```c
/* ===== 初始化（CubeMX 生成后，这里只差启动） ===== */
HAL_TIM_Base_Start_IT(&htim3);   /* 启动，并打开更新中断 */
```

```c
/* ===== 中断处理：全局中断函数里调 HAL 分发 ===== */
void TIM3_IRQHandler(void) {
    HAL_TIM_IRQHandler(&htim3);
}
/* ===== 回调：每 1ms 进一次，在这里干活 ===== */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance == TIM3) {
        /* 每秒计数一次；或翻转 GPIO 做"呼吸灯/心跳灯" */
        /* 别在中断里干重活（printf、大循环），只做短操作或置标志 */
    }
}
```

要点：

- 回调里 `if (htim->Instance == ...)` 判断是哪路定时器——一个回调函数服务所有定时器
- **软件定时器**（如 `HAL_GetTick` 即基于 SysTick）和**硬件定时器**是两回事：前者是系统滴答，后者是外设，别混
- 定时精度：硬件定时器由晶振时钟驱动，比软件延时（`HAL_Delay`）准得多；`HAL_Delay` 只适合毫秒级且不严格的场合

## 五、三大基本用法之二：PWM 输出

把 CNT 和 CCR 比较，输出引脚就变成方波——这就是 PWM。CubeMX：TIM → `PWM Generation CHx`，设 `Prescaler`、`Counter Period`、`Pulse(CCR 初值)`，`Mode` 选 `PWM1`，引脚在 GPIO 页确认。

```text
频率 = 定时器时钟 / (PSC+1) / (ARR+1)
占空比 = CCR / (ARR+1)          ← 高电平所占比例
```

```c
/* ===== 启动 PWM ===== */
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
```

```c
/* ===== 运行时改占空比（最常用） ===== */
__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, 500);   /* CCR=500，占空比 500/(ARR+1) */
```

要点：

- **PWM1 vs PWM2**：PWM1 是"CNT < CCR 时输出高"，PWM2 相反。习惯用 PWM1，别乱切
- **占空比能到 0 和 100%**：CCR = 0 → 恒低；CCR ≥ ARR → 恒高（PWM1 下）。做"先灭再渐亮"时利用这个特性
- **改频率要小心**：运行时改 ARR 可以变频率，但**占空比也会跟着变**（因为分母变了）。想只调占空比就只动 CCR，想只调频率就把 CCR 按比例一起改
- **高级定时器的 PWM 要连死区**：用 TIM1/8 推半桥时，占空比不能超过 50% 太多，且必须开互补+死区（见第十节），否则上下管直通

## 六、三大基本用法之三：输入捕获

用定时器**测外部信号的频率、周期、脉宽**。原理：信号沿一来，定时器把 CNT 的快照存进 CCR，你可以从两次快照之差算出时间。

CubeMX：TIM 的某通道设 `Input Capture direct mode`，选触发沿（上升/下降/双沿），`Prescaler` 设小（捕获建议 1 或 2 分频），`Filter` 可加输入滤波。核心是 `HAL_TIM_IC_CaptureCallback`。

```c
HAL_TIM_IC_Start_IT(&htim3, TIM_CHANNEL_1);   /* 启动捕获，沿一到就进回调 */

uint32_t last, period;
void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim) {
    if (htim->Channel == HAL_TIM_ACTIVE_CHANNEL_1) {
        uint32_t now = HAL_TIM_ReadCapturedValue(&htim3, TIM_CHANNEL_1);
        if (last) {
            period = now - last;                       /* 两次沿之间的计数差 = 周期 */
            /* 频率 = 计数频率 / period */
        }
        last = now;
    }
}
```

### 测量脉宽：用「双沿」或两个通道

- 一个通道测**周期**：同一沿（都测上升沿），两次捕获之差即一个周期
- 一个通道测**脉宽**：先测上升沿，再测下降沿，两次之差即高电平宽度；用 `TIM_IC_SELECTION_DIRECTTI` 自动在沿变化处捕获
- 也可以用**两个通道**（CH1 采上升沿、CH2 采下降沿，互为间接），数据量大或要同时测周期+脉宽时用

### 测速（转一圈多少脉冲）与测频率的差别

- **测频率**：固定计数频率，测"两次沿之间几个数" → 分辨率随频率变化，低频时分辨率差
- **测周期再取倒数**：高频信号适合数周期，低频信号适合直接测周期。工程上常用"低频测周期、高频测频率"，两者互补
- **测转速（编码器/霍尔）**：见第九节，用专用接口更好，不要拿输入捕获硬拼

## 七、中断与优先级：别让回调互相打架

定时器中断涉及两个 NVIC 优先级，配错了轻则卡死、重则回调不执行：

| 项 | 配置位置 | 常见坑 |
| -- | -------- | ------ |
| **抢占优先级** | NVIC 优先级分组 + 每个中断的 Preemption Priority | 与 RTOS 冲突：FreeRTOS 要求 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 以下的优先级里不能调 RTOS API |
| **子优先级** | 同抢占下分先后 | 同抢占优先级时按子优先级排队 |

- **回调里不调 RTOS 阻塞 API**：`osDelay`、信号量阻塞都别在中断回调里直接调，要用 `osSemaphoreRelease` 之类 ISR 安全版，或 `cmsis_os2` 的 `osKernelGetTickCount` 比较时间
- **一个外设一个 IRQHandler**：TIM3 的更新、捕获、PWM 全走 `TIM3_IRQHandler` 里的 `HAL_TIM_IRQHandler`，由 HAL 按标志分发到不同回调，别自己写两套
- **中断里只置标志、主循环消费**：数据搬运、协议解析放主循环，中断里做多了就丢中断

## 八、隐藏功能之一：触发链（定时器之间、定时器给 ADC/DAC 当扳机）

这是 STM32 定时器最值钱、也最容易被忽略的能力——**定时器之间可以互相触发、级联**，还能**给 ADC/DAC 发触发信号**，让「精确时刻采样」不再依赖 CPU 代码执行时间。

### 主从模式：谁是主、谁是从

每个定时器有两面：作为**主（Master）**，它能输出触发信号 TRGO；作为**从（Slave）**，它能吃别的定时器的信号。

- **主定时器的 TRGO 可以输出**：更新事件、输出比较、OC1REF、触发输入等（`TIMx_CR2.MMS` 选择）
- **从定时器的从模式（Slave Mode）**有几种玩法（`TIMx_SMCR.SMS`）：

| 从模式 | 作用 | 典型用法 |
| ------ | ---- | -------- |
| **外部时钟模式 1（External Clock 1）** | 别人给一个信号，你按它的边沿数数 | 定时器级联，放大计数范围 |
| **门控模式（Gated）** | 信号高电平期间你才计数 | 用一路 PWM 精确门控另一路的计时窗口 |
| **触发模式（Trigger）** | 收到触发信号才启动计数 | 同步启动多个定时器 |
| **复位模式（Reset）** | 收到触发信号就清零重数 | 同步周期 |

### 级联：用多个 16 位定时器拼一个大计数器

单个 16 位定时器最大 ARR 是 65535，数完就溢出。**级联**后可以拼成 32 位甚至更大：主定时器的更新事件作为从定时器的时钟（`TIMx_SMCR` 配外部时钟模式，主定时器更新 → 从定时器 +1），主计数 65535 次、从计数一次，合起来就是 32 位。

```c
/* 级联思路：TIM2 主，TIM3 从 */
/* TIM2: 计数到 ARR 翻篇，翻篇时输出更新事件（TRGO） */
/* TIM3: 把 TRGO 当外部时钟，TRGO 一下 CNT+1，CNT 值即"TIM2 翻篇了几次" */
```

**看时序用逻辑分析仪/示波器比看寄存器靠谱**，级联的时序关系三言两语说不清，波形一看就懂。

### 最经典应用：定时器触发 ADC（精确采样率）

ADC 需要"每隔固定时间采一次"，如果每次都用软件触发，采样时刻就由代码执行时间决定、会抖动。**用定时器 TRGO 触发 ADC**，采样时刻精确到定时器时钟的纳秒级，CPU 完全不参与时序：

```c
/* CubeMX：ADC 的 External Trigger Conversion Source 选某定时器的 TRGO，
   那个定时器里开 Trigger Output (TRGO) = Update Event */
HAL_ADC_Start_DMA(&hadc1, adc_raw, 48);   /* 定时器一翻篇，ADC 自己采、DMA 自己搬 */
```

配合 **DMA + 循环模式**，就是"定时器定节奏、ADC 采、DMA 搬"一条龙，CPU 全程不沾手——做 FFT、音频采样、电机电流波形采样的标准姿势。触发细节见 [stm32-adc.md](stm32-adc.md) 第四节。

!!! warning "F1 触发命名的坑"
    F1 的触发源宏名（如 `T2_TRGO`）实际可能映射到某通道事件而非 TRGO 本身，**以 CubeMX 下拉框 + 参考手册触发映射表为准**，别只看宏名。

### 定时器也能触发 DAC

基本定时器（TIM6/7）虽然没有输出通道，但专门承担"给 DAC 发触发"的职责——DAC 输出阶梯波、任意波形时，用定时器定节奏触发 DAC，波形平滑且不占 CPU。DAC 细节见 [stm32-dac.md](stm32-dac.md)。

## 九、隐藏功能之二：编码器模式与霍尔传感器

### 编码器模式：读正交编码器，自动判断方向

**正交编码器**输出两路相位差 90° 的信号 A/B，定时器配成**编码器模式**后，硬件自动根据 A/B 的相位关系让 CNT **加减**——正转 CNT 加、反转 CNT 减，方向自动判断，**不用 CPU 去数**。

```c
/* CubeMX：TIM 的两个通道都配 Encoder Mode，计数方式选 X2 或 X4 */
TIM_Encoder_InitTypeDef sConfig = {0};
sConfig.EncoderMode = TIM_ENCODERMODE_TI1;
/* 计数分频：TI1/TI2 各采每沿或每两个沿，X4 精度最高 */
HAL_TIM_Encoder_Start(&htim3, TIM_CHANNEL_ALL);
```

- 读数：`__HAL_TIM_GET_COUNTER(&htim3)`，直接就是"走了多少个步进"
- **溢出要处理**：16 位 CNT 数到 65535 再正转就溢出回到 0，转速或累计量大的要在更新中断里扩展成 32 位
- **测转速公式**：`转速(rpm) = (计数差 / 每转脉冲数) × 采样周期换算`，每转脉冲数要看编码器线数（如 1000 线 + X4 = 4000 步/转）
- 别用输入捕获硬拼编码器：捕获模式要 CPU 介入，编码器模式是硬件自动的，实时性和资源占用都更好

### 霍尔传感器模式：测 BLDC 电机转子位置

TIM1/8 支持把三个霍尔信号直接接进定时器，硬件自动根据霍尔组合判断转子位置、控制换相。适合无刷电机（BLDC）驱动，属于电机控制专题，知道"有这个模式、别用普通捕获硬凑"即可。

## 十、隐藏功能之三：高级定时器的高级特性

TIM1/8 是高级定时器，除了通用定时器的全部功能，还多了几个**电机控制专属**的保命功能：

### 互补输出 + 死区

驱动半桥/全桥（两个 MOS 管串联）时，**上下管绝不能同时导通**，否则电源直通、瞬间烧板。高级定时器提供：

- **互补输出**：同一对通道输出两个逻辑相反的信号（`TIM_CHANNEL_1` 和 `TIM_CHANNEL_1N`），一个高一个低
- **死区时间**：让互补的切换**中间留一段两管都关断的时间**，防止"上管还没关死、下管就开了"的直通

```c
/* 配置死区时间（CubeMX 的 Break/Deadtime 页，或 HAL 的 TIM_BreakDeadTimeConfigTypeDef） */
/* 死区时长 = 一个计数时钟 × 死区值，F1 最高到几 µs 级，按管子开关速度选 */
HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1);
HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1N);   /* 互补通道也要启动 */
```

- **死区不是越大越好**：太小防不了直通，太大波形变差、电机噪声大。按所用 MOS 管的总开关时间（tr+tf）留 1.5~2 倍余量
- 普通通用定时器（TIM2/3/4/5）**没有**互补和死区，别拿它们推半桥

### 刹车（Break）功能

检测到故障（过流、过压、急停信号）时，**硬件自动把全部 PWM 输出置为安全电平**（或高阻），比软件关中断快得多——电机控制里"故障了必须立刻停"就靠它。

```c
/* 配置 Break 输入与极性（CubeMX 的 Break/Deadtime 页），
   或 HAL_TIMEx_ConfigBreakDeadTime */
/* 触发后 PWM 输出立即变安全电平，软件再处理"为什么停了" */
```

- 刹车的可靠性是**纯硬件**的：即使 CPU 正在忙、被中断淹没，刹车输入一拉，输出照样立刻安全
- 复位刹车要靠软件显式清标志（`__HAL_TIM_MOE_ENABLE` 重开输出），别自动恢复，否则故障没消除就重新输出会二次烧板

### 重复计数器（RCR）：N 次更新才中断一次

高级定时器多一个 `TIMx_RCR`（重复计数器）：CNT 翻篇 N 次才产生一次更新事件。用处在"要每隔多个周期才响应一次"的场合——比如波形每 4 个周期才处理一次，省中断。

## 十一、隐藏功能之四：DMA 与「波形合成」

### 定时器 + DMA：不用 CPU 也能改变 ARR/CCR

定时器触发 DMA，让 DMA 自己搬数据去改 CCR（占空比）或 ARR（频率）——这就是**查表法合成任意波形**的硬件基础：

```c
/* 思路：把一整段波形采样值放数组里，定时器每次更新触发 DMA 搬下一个值到 CCR，
   输出引脚就连续扫出这段波形 —— 全程无 CPU 干预 */
/* DMA 配 Memory-to-Peripheral，Peripheral 是 CCR 寄存器，循环模式 */
HAL_TIM_PWM_Start_DMA(&htim3, TIM_CHANNEL_1, (uint32_t*)waveform, N);
```

- 和 ADC 的 DMA 是同一个 DMA 控制器，**共用 DMA 通道表**，多路 DMA 同时用要留意优先级
- 搬数据的 CCR 寄存器地址要用**正确的大小**（CCR 是 16 位寄存器），DMA 位宽配错会越界

### 基本定时器的 DMA：批量刷新外设

基本定时器（TIM6/7）没有输出通道，但可以**定时触发 DMA 把数据搬到别的寄存器**——比如定时刷新 DAC 数据寄存器输出波形、定时搬运显示缓冲。定时器在这里是"节拍器"，DMA 是"搬运工"。

## 十二、隐藏功能之五：几个容易踩的细节

### 读数要防"读到一半进位"

**读取一个正在跑的定时器计数器**，16 位计数在进位瞬间可能读到跨位的错值（比如从 0xFFFF 进位到 0x10000 时，低 16 位已回 0、高 16 位还没加）。处理办法：

- **连续读两次**，两次相同才算数（半数的场景够用）
- 用 **TIM2/5 的 32 位计数器**，一次 `__HAL_TIM_GET_COUNTER` 读完整值，省去拼装
- 配合更新中断做"扩展位数"的计数，读 CNT + 扩展位拼完整

### 影子寄存器：改了值要等下一次更新才生效

前面说过，ARR/PSC 有影子机制。**想立刻生效就主动产生一次更新事件**：

```c
__HAL_TIM_SET_AUTORELOAD(&htim3, 1999);        /* 先写值 */
__HAL_TIM_SET_COUNTER(&htim3, 0);              /* 清零 CNT */
__HAL_TIM_GENERATE_UPDATE(&htim3);             /* 强制产生一次更新，让新值装载 */
```

### 分辨率：ARR 越大，占空比越细

`占空比步进 = 1/(ARR+1)`。要 1% 精度的占空比，ARR ≥ 99；要 0.1%，ARR ≥ 999。**先定频率和 PSC，再尽量把 ARR 拉大**，占空比可调档位才多——这是 PWM 设计里很基础但常被忽略的一条。

### 分频系数和倍率记忆点

- PSC、ARR 都要 **+1** 再用（`PSC+1`、`ARR+1`），记错这个差 1 最常见
- 16 位最大 65535，32 位（TIM2/5）能到 4G，长周期定时/大计数别硬塞 16 位
- 挂 APB1 的定时器时钟在 APB1 分频≥2 时自动 ×2（见第二节），和挂 APB2 的 TIM1/8 不一定同频

## 十三、常见坑汇总

- **时钟按 APB 算，结果差一倍** → 忘了"APB 预分频≥2 时定时器时钟 ×2"（第二节）。
- **PSC/ARR 忘了 +1** → `PSC+1`、`ARR+1`，别按原始值算频率。
- **改了 ARR/PSC 不生效** → 影子寄存器要等下一次更新事件，手动 `__HAL_TIM_GENERATE_UPDATE` 强制生效（第十二节）。
- **占空比和频率一起变** → 改 ARR 会连带改占空比，只调占空比动 CCR，只调频率按比例一起改（第五节）。
- **拿通用定时器推半桥** → 没有死区会直通烧板，半桥/全桥必须用 TIM1/8 的高级 PWM（第十节）。
- **编码器溢出没处理** → 16 位 CNT 溢出回 0，转速/累计量要在更新中断扩展位数（第九节）。
- **回调里调阻塞 API** → 中断回调只置标志、主循环消费，RTOS 下别直接 `osDelay`（第七节）。
- **定时器触发 ADC 不生效** → 先查从定时器触发源（TRGO）有没有开，再查 ADC 的触发边沿配了没，最后查 NVIC。
- **读数读到进位错值** → 连续读两次判同，或直接用 32 位定时器（第十二节）。
