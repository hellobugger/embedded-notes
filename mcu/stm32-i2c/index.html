    STM32 I2C：从两根线讲透软件 IIC / 硬件 I2C / DMA / SMBus

    一句话：I2C 是两根开漏线上的「单向喊话」——主设备一根时钟线（SCL）一根数据线（SDA），先喊地址点名（谁应答谁上场），再一个字节一个字节地交换数据，每传完一个字节听一声回应（ACK）。要讲清楚的其实是六件事——这两根线凭什么能传数据（通信机制与时序）、同一个接口为什么有「软件」和「硬件」两种做法（软 IIC vs 硬 I2C）、硬件 I2C 怎么配（配置说明）、怎么把 CPU 从搬字节里解放出来（DMA）、还有一条「带规则的 I2C」叫什么（SMBus）、以及工程上踩过的坑（避坑备忘）。本文以 F1/F4 的 HAL 为例，寄存器名与配置以 HAL 为准。

    一、通信机制：两根线怎么就把事办了

    I2C 只有 两根线：SCL（时钟线） 和 SDA（数据线）。和 UART/SPI 不同，I2C 是 主从结构——一个主设备（通常就是 MCU）发起点名和数据，一个或多个从设备（传感器、EEPROM、RTC、显示屏驱动）响应。用一句话理解它的性格：

    I2C 是一个「多人共用的电话线」，大家都不说话时拉着（空闲），谁要说话就把它拉下来（占用）。主设备喊名字（地址），被喊到的人应答，然后按主设备的节奏一个字节一个字节对话。

    1.1 开漏 + 上拉电阻：为什么两根线能多人共用

    这是 I2C 最根本的物理设计，理解了它，后面所有「为什么」都顺了：

    • SCL/SDA 都是开漏（Open-Drain）输出：器件只能把线拉低（输出 0），不能主动输出高。
    • 线上各挂一个上拉电阻（通常 4.7kΩ / 2.2kΩ / 10kΩ），不拉时靠电阻把线拉回高电平。
    • 所以 SDA 高 = 1，SDA 低 = 0，总线空闲时两根线都是高。
    • 好处：任意一个器件都可以拉低总线，天然支持多主（只要不打架）；坏处是速度被上拉电阻和总线电容限制（上拉越慢、线越长，上升沿越缓，速度越上不去），这也是 I2C 标准速率只有 100k/400k/1M 的原因。

    开漏不是漏了

    开漏是「只能拉低、不能推高」的意思。新板子上 I2C 不工作，第一步先量 SCL/SDA 是否有上拉电阻——很多模块（尤其 OLED、RTC）板载有上拉，而你自己画的板子如果忘了，就只剩两根悬空的线，通信全无。

    1.2 总线时序：先点名，再对话

    一次完整的 I2C 通信叫一次 传输（Transaction），分三步：起始 → 逐字节收发 → 停止。时序按 SCL 的电平节奏来：

    阶段 时序 含义
    起始位 START SCL 高时，SDA 从高拉低 宣告总线占用，所有从机开始「听」
    地址 + 读写位 8 位：7 位地址 + 1 位 R/W（0=写，1=读） 点名的对象 + 这次要读还是要写
    应答 ACK / 非应答 NACK 第 9 个时钟：SDA 低=ACK，高=NACK 被点名的从机拉低应答，否则 NACK
    数据字节 每字节 8 位，高位在前，之后 1 位 ACK 按主设备节奏逐字节传
    停止位 STOP SCL 高时，SDA 从低拉高 释放总线，传输结束

    一张最关键的图（数据只在 SCL 高时有效，SCL 低时才能变化）：

          ┌─┐   ┌─┐   ┌─┐   ┌─┐   ┌─┐         SCL
  ────┘ └───┘ └───┘ └───┘ └───┘ └────────
   ┌───────┐   ┌───────┐   ┌───────┐
   │ D7(D6)│   │ D5(D4)│   │ D3(D2)│      SDA（高电平期间稳定，低电平期间可变）
   └───────┘   └───────┘   └───────┘
   ←数据有效窗口→  ←数据有效窗口→
        ▲   ▲         采样点：SCL 高电平中段
    • 数据位：SCL 高电平期间 SDA 必须保持稳定，SCL 低电平期间 SDA 才能改变——这是协议铁律。
    • 采样点：接收方在 SCL 高电平的中段读 SDA。
    • 地址：7 位地址 + R/W 位组成第一个字节。常见从设备地址如 EEPROM 24C02（0xA0 写 / 0xA1 读）、OLED 0x78、RTC DS3231 0xD0。
    • 应答：每个字节传完，接收方在第 9 个时钟拉低 SDA 表示 ACK。写 EEPROM 时每写一字节都要等它 ACK；读数据最后可以不 ACK（NACK）告诉从机「读够了，别发了」。

    1.3 速率与时钟

    I2C 总线由 SCL 的时钟决定速率，标准分四档：

    模式 速率 说明
    标准模式（Standard） 100 kbit/s 老设备默认
    快速模式（Fast） 400 kbit/s 日常最常用
    快速模式+（Fast+） 1 Mbit/s 需要更小上拉电阻
    高速模式（Hs） 3.4 Mbit/s 少见，F1/F4 不支持

    波特率公式（硬件 I2C 由外设时钟分频而来）：

    SCL = PCLK / (CLK 分频系数)      // 不同 MCU 公式不同，F1/F4 见下节配置

    工程上 400kHz（Fast 模式） 是绝大多数 I2C 传感器的默认要求，CubeMX 里选 Fast Mode，CubeMX 会自动算好分频。

    1.4 与 SPI / UART 的对比：什么时候选谁

    维度 I2C SPI UART
    线数 2 根（SCL+SDA） 4 根（SCLK+MOSI+MISO+CS） 2 根（TX+RX）
    结构 主从，可多从（7 位地址最多 128 个从机） 主从，一主多从（靠 CS 片选） 点对点，无地址
    速度 100k~1M 数十 MHz（最快） 取决于波特率（通常 ≤几 Mbps）
    全双工 ❌ 半双工（同一根线读和写分时） ✅ 全双工 ✅ 全双工
    硬件握手 ✅ 有 ACK（可靠） ❌ 无（发出去不管） ❌ 无
    总线仲裁 ✅ 支持多主 ❌ ❌
    最省引脚 ✅ ❌ ✅

    怎么选：接线紧张选 I2C；追求速度选 SPI；一对一的可靠串口选 UART。I2C 是传感器、EEPROM、RTC 的默认总线，SPI 是高速外设（Flash、ADC、LCD）的默认总线。

    二、软件 IIC vs 硬件 I2C：同一件事的两种做法

    这是 I2C 专题最核心的辨析。同一个外设，为什么有的工程师「用 GPIO 自己模拟」，有的用「芯片自带的 I2C 外设」？ 区别不是功能不同，而是实现主体不同——软件 IIC 用 CPU 逐位翻转 GPIO，硬件 I2C 用芯片内部的专用外设自动管理时序。

    2.1 软件 IIC：用 GPIO 模拟时序

    软件 IIC 是不依赖芯片自带的 I2C 外设，直接用两个普通 GPIO 口模拟出 SCL/SDA 的时序。一个最简单的位收发核心逻辑：

    /* 软件 IIC 的核心：一个 GPIO 翻转 + 延时，模拟 SCL/SDA */
#define IIC_SCL_1()  HAL_GPIO_WritePin(SCL_GPIO_Port, SCL_Pin, GPIO_PIN_SET)
#define IIC_SCL_0()  HAL_GPIO_WritePin(SCL_GPIO_Port, SCL_Pin, GPIO_PIN_RESET)
#define IIC_SDA_1()  HAL_GPIO_WritePin(SDA_GPIO_Port, SDA_Pin, GPIO_PIN_SET)
#define IIC_SDA_0()  HAL_GPIO_WritePin(SDA_GPIO_Port, SDA_Pin, GPIO_PIN_RESET)
#define IIC_SDA_READ() HAL_GPIO_ReadPin(SDA_GPIO_Port, SDA_Pin)

static void IIC_Delay(void) { for (volatile int i = 0; i < 40; i++) ; }  /* 空转延时 */

/* 发送 1 个字节：MSB 在前，SCL 高时 SDA 稳定 */
static void IIC_SendByte(uint8_t byte) {
    for (int i = 0; i < 8; i++) {
        (byte & 0x80) ? IIC_SDA_1() : IIC_SDA_0();
        byte <<= 1;
        IIC_Delay();
        IIC_SCL_1(); IIC_Delay();   /* SCL 拉高：数据被采样 */
        IIC_SCL_0(); IIC_Delay();
    }
}

    它的本质是：把协议里的每一拍（起始位、每 8 位、ACK）都拆成「拉 GPIO + 延时」的指令序列，由 CPU 一条条执行。延时函数决定速率，通常靠空循环（delay loop）实现，不精确、但能跑。

    2.2 硬件 I2C：专用外设接管

    硬件 I2C 用的是芯片内部专门的 I2C 外设（F1 的 I2C1/2，F4 的 I2C1/2/3），它内置状态机，自动处理起始/停止/地址/ACK/数据位，CPU 只需要「写一个寄存器让外设发一字节，然后等它完成中断/标志位」。

    /* 硬件 I2C：CPU 只填缓冲和长度，外设自动做时序 */
HAL_I2C_Master_Transmit(&hi2c1, 0xA0, txData, len, HAL_MAX_DELAY);

    它的本质是：时序由硬件状态机负责，CPU 不参与逐位翻转。CPU 关心的只是「开始、完成、出错」，用的是芯片厂商已经调好、带容错的成熟实现。

    2.3 逐维度对比

    对比维度 软件 IIC 硬件 I2C
    实现主体 CPU 逐位翻转 GPIO，靠空循环延时 芯片自带 I2C 外设（状态机），硬件自动时序
    引脚需求 任意 2 个 GPIO，无特殊要求 必须接在 I2C 专用引脚（如 F1 的 PB6/PB7）
    时序精度 取决于延时循环，受中断/编译优化影响，有抖动 硬件时钟精确，稳定
    波特率 由延时决定，不精确（约几十~几百 kHz） 精确可配置（100k/400k/1M）
    CPU 占用 高，每个位都要 CPU 忙等延时 低，字节级可交给中断/DMA（见第四节）
    可靠性 无硬件错误检测，出错难定位 有硬件错误标志（超时/仲裁/总线错误），HAL 能查错误码
    支持多主/仲裁 ❌ 不支持 ✅ 支持（硬件仲裁）
    速率上限 受 GPIO 翻转速度 + 中断影响，通常难上 1M 最高 1M（Fast+，F4 部分支持）
    对中断敏感 严重，中断打断会破坏时序 弱，时序由硬件保证
    可移植性 跨芯片强（任何 GPIO 都能模拟） 强（HAL 封装统一，但引脚要换）
    代码量 / 依赖 自写 ~100 行，零依赖 依赖 HAL 库，初始化结构体较多
    调试难度 自己挖的坑自己埋，可读性差 有标准错误码，但初始化配置复杂

    2.4 到底用哪个：一张决策表

    场景 推荐
    传感器 / EEPROM / RTC 常规读写，追求稳定可靠 硬件 I2C（默认首选）
    新板子刚回来、先快速点亮一个模块验证硬件 软件 IIC（几分钟就能跑，不依赖 CubeMX 配置，方便排硬件）
    引脚被占用，只能用两个不支持的 GPIO 口 软件 IIC
    跑 RTOS，需要规避硬件 I2C 在中断里忙等的坑 两者都行，但优先硬件 I2C + 中断/DMA
    对时序敏感（如高速传感器、音频） 硬件 I2C
    跨平台移植（代码要在多型号 MCU 复用） 软件 IIC（或封装好的一层抽象）

    工程惯例：能用硬件就用硬件

    硬件 I2C 的坑（忙等、锁死、配置复杂）大多发生在不了解它时。把 HAL 的超时参数配好、用中断/DMA 代替阻塞调用后，硬件 I2C 是比软件 IIC 更省心、更可靠的选择。软件 IIC 适合调试早期和引脚受限的场合，作为「兜底方案」存在。

    三、硬件 I2C 配置说明：CubeMX + HAL

    3.1 CubeMX 页面（F4 为例，F1 类似）

    Connectivity → I2C1，关键参数：

    参数 说明 典型值
    Mode I2C / I2C 多主 / SMBus 主机 / SMBus 从机 I2C
    Speed Mode Standard（100k） / Fast（400k） / Fast+（1M） Fast（400k，最通用）
    I2C Speed 具体波特率，选 Fast 后自动算 400000
    Rising Time 上升沿时间（ns），跟总线上拉电阻、电容相关 自动算好，一般不动
    Falling Time 下降沿时间（ns） 自动算好
    Analog Filter / Digital Noise Filter 滤除毛刺，抑制干扰 默认开启，保留
    Address Mode 7 位 / 10 位地址 7 位（默认，绝大多数从设备）
    Own Address 本机从机地址（做从机时用） 主模式一般不管

    勾选上方 NVIC Settings → I2C1 event / error interrupt，生成代码才能用中断/DMA 收发。

    3.2 HAL 初始化结构体逐字段

    I2C_HandleTypeDef hi2c1;

hi2c1.Instance             = I2C1;
hi2c1.Init.ClockSpeed      = 400000;          /* 目标波特率：400k = Fast 模式 */
hi2c1.Init.DutyCycle       = I2C_DUTYCYCLE_2; /* 占空比：2=50%，16/9 是给 1M 用的 */
hi2c1.Init.OwnAddress1     = 0;               /* 本机从机地址（主模式用不到） */
hi2c1.Init.AddressingMode  = I2C_ADDRESSINGMODE_7BIT;  /* 7 位地址 */
hi2c1.Init.DualAddressMode = I2C_DUALADDRESS_DISABLE;
hi2c1.Init.GeneralCallMode = I2C_GENERALCALL_DISABLE;  /* 广播呼叫 */
hi2c1.Init.NoStretchMode   = I2C_NOSTRETCH_DISABLE;    /* 时钟拉伸，见下 */
HAL_I2C_Init(&hi2c1);

    3.3 时钟拉伸（Clock Stretching）：从机让主机「等一下」

    I2C 里有个「从机拖时间」的机制：从机处理不过来时，可以把 SCL 拉低不放，主设备读到 SCL 一直低就知道「对方忙，等等」。这就是时钟拉伸。

    • 从机慢、主设备快时容易触发（比如 EEPROM 写周期、OLED 刷新）。
    • NoStretchMode 置为 DISABLE（允许拉伸）是最常见的配置，让从机有机会拖时间。
    • 阻塞式（轮询）主模式天然「等得起」，因为 CPU 就在忙等；中断/DMA 模式靠超时检测来兜底——主机一直等不到 SCL 释放，最终报超时错误（HAL_I2C_ERROR_TIMEOUT）。所以配置超时参数是硬件 I2C 的必修课，见下。

    3.4 超时（Timeout）：硬 I2C 最容易被忽略的一环

    硬件 I2C 的阻塞函数都有超时参数：

    HAL_I2C_Master_Transmit(&hi2c1, addr, data, len, HAL_MAX_DELAY);
/*                                                         └─────┬─────┘
                                                        超时 ms：超过即返回错误
                                                        HAL_MAX_DELAY = 阻塞永远等（不建议） */
    • 阻塞模式里传 HAL_MAX_DELAY 意味着「永远等」，如果总线卡死（从机没接、SDA 被拉死），CPU 会一直卡在函数里，这在生产代码里是灾难。
    • 正确做法是给一个合理超时（如 100ms），超时后函数返回错误码，应用层可以重试或上报： 
      if (HAL_I2C_Master_Transmit(&hi2c1, 0xA0, buf, 2, 100) != HAL_OK) {
    /* 超时或出错：检查线路、从机是否上电、地址是否对 */
}

    3.5 HAL 提供的三套接口

    HAL 的 I2C 函数分轮询 / 中断 / DMA 三档，这也是第四节 DMA 的入口：

    方式 函数 特点
    轮询 HAL_I2C_Master_Transmit / Receive 阻塞忙等，简单但卡 CPU
    中断 HAL_I2C_Master_Transmit_IT / Receive_IT 立即返回，完成后回调 HAL_I2C_MasterTxCpltCallback
    DMA HAL_I2C_Master_Transmit_DMA / Receive_DMA 数据自动搬运，完成回调，最省 CPU

    从机侧还有一套：HAL_I2C_Slave_Transmit / Receive，设备做从机时用（比如被另一个主机点名读数据）。

    3.6 最容易翻车的一个坑：HAL 的忙等和锁死

    硬件 I2C 的阻塞调用（轮询）在 HAL 里的实现是「轮询状态寄存器 + 延时重试」，它不是真的中断驱动。两个高频坑：

    • HAL_I2C_Master_Transmit 轮询在中断回调里调用会死锁：阻塞函数内部会调用 HAL_Delay 并等状态，在中断上下文调用会卡死（HAL_Delay 依赖 SysTick 中断）。中断/DMA 回调里只置标志，收发放到主循环。
    • I2C_BUSY 标志卡住：上次传输没正常结束（比如被中断打断、超时），状态寄存器里 BUSY 一直不释放，下次调用直接返回忙。清法：调用 HAL_I2C_DeInit + HAL_I2C_Init 复位外设，或写 I2C1->CR1 的 SWRST 位复位。
    • 引脚复用（Alternate Function）没配对：GPIO 要选 I2C 的 AF（如 F4 的 AF4），且要开上拉。开漏 + AF + 上拉，三样缺一不可，这是硬件 I2C 不工作的头号原因。

    四、DMA：把搬字节的活交给硬件

    4.1 为什么要 DMA

    I2C 每传一个字节，CPU 都要「从内存搬一次」或「收一次」再到下一个字节。当数据量大、或者 CPU 要同时忙别的事（电机控制、RTOS 任务）时，这个「每字节搬一次」的开销就不能忍了。DMA（Direct Memory Access） 是一条独立的搬运通道：CPU 只需要告诉它「从哪搬到哪、搬多少」，剩下每字节的搬运全部由 DMA 控制器在后台完成，搬完才通知 CPU。

    一句话：轮询是 CPU 亲自搬货，中断是 CPU 被叫去搬货，DMA 是雇了个搬运工（DMA 控制器）自己搬，搬完才喊你收货。

    4.2 HAL 的 DMA 收发流程

    DMA 模式下，CPU 的工作量降到一个「发起」+ 一个「收尾回调」：

    /* 发送：告诉 DMA 把 txData 搬出去，返回后 CPU 立刻继续干别的 */
HAL_I2C_Master_Transmit_DMA(&hi2c1, 0xA0, txData, 32);

/* 搬完了，回调里收尾 */
void HAL_I2C_MasterTxCpltCallback(I2C_HandleTypeDef *hi2c) {
    /* 数据已全部发出：可以释放缓冲、置标志、或接着发起下一段 */
}

/* 接收：把收到的 32 字节由 DMA 直接放进 rxData */
HAL_I2C_Master_Receive_DMA(&hi2c1, 0xA1, rxData, 32);
void HAL_I2C_MasterRxCpltCallback(I2C_HandleTypeDef *hi2c) {
    /* rxData 里已经有 32 字节，直接使用 */
}

    地址自增：DMA 搬的时候，源/目的内存地址自动 +1（MemoryDataWidth 配置），CPU 不用管。搬完触发完成中断 → 回调，中间 CPU 完全不介入。

    4.3 CubeMX 里怎么开 DMA

    在 CubeMX 中 I2C 页面 → DMA Settings 添加两个通道：

    通道 方向 说明
    DMA1 通道 x（TX） Memory to Peripheral 发送：内存 → I2C
    DMA1 通道 y（RX） Peripheral to Memory 接收：I2C → 内存
    • Mode 选 Normal（默认），Memory Increment 开（地址自增），Data Width 按 1 字节设即可（I2C 是字节流，8 位即可）。
    • 两个通道要在 CubeMX 里配好并全局使能（NVIC 勾上 DMA 中断），生成代码后 HAL_I2C_Master_Transmit_DMA 才能工作。

    4.4 DMA 的坑与边界

    • DMA 回调里不要再开 DMA：回调里调用下一个 _DMA 函数在 HAL 某些时序下会重入异常（和 CAN 一样的道理）。改在主循环/任务里发起下一段。
    • DMA 目标缓冲要常驻：DMA 是「异步搬」，你传入的 txData/rxData 必须是生命周期覆盖整个传输的变量（static 或全局或 RTOS 队列缓冲），不能是函数栈上的一次性局部变量——函数返回了 DMA 还在搬，读到的就是悬空内存。这是 DMA 调试最经典的崩溃原因。
    • 每次传输结束要等完成回调再改缓冲：发送完但回调没来，txData 不能急着改写。
    • DMA 不是所有量都值得：只有几十字节以下的小数据，轮询/中断可能更快（省去 DMA 的配置开销）；大量数据（几 KB 的 EEPROM 页、显示屏帧缓冲）才明显受益。
    方式 CPU 占用 实时性 适合量级 适合场景
    轮询 最高（全程忙等） 最差（被占用期间干不了别的） 小、低频 初始化自检
    中断 中（每字节被打断一次） 好 中 日常收发
    DMA 最低（搬完才打断） 好 大、高频 大块数据、RTOS 场景

    五、SMBus：带「规矩」的 I2C

    SMBus（System Management Bus，系统管理总线）长得像 I2C，但比 I2C 更「严格」。它是从 I2C 演化而来的，用在电池、电源管理、传感器、服务器主板等系统管理场景。理解 SMBus 的正确姿势是：SMBus 是 I2C 的一个「超集 + 约束集」——线、时序、主从模型都一样，但加了超时、分组协议、报警机制等规则。

    5.1 SMBus 与 I2C 的关键区别

    维度 I2C SMBus
    标准 通用总线，随意用 系统管理总线，有明确定义的协议
    最高速率 100k/400k/1M 100 kHz（固定，大部分设备是 100k）
    最小速率 / 超时 无规定（可无限慢） 有超时：从机必须在 25ms 内响应，否则视为故障
    地址 7 位，地址空间大 7 位，但保留了特定保留地址（如广播、SMBus 主机地址）
    时钟拉伸限制 从机可以无限拉伸 SCL 拉伸上限 25ms，防止从机拖死总线
    分组/寻址 无（自己定协议） 定义好的命令协议（读/写命令寄存器，有标准命令集）
    PEC 校验 ❌ 无 ✅ 可选 PEC（包错误校验）：多 1 字节 CRC 校验
    报警 ❌ 无 ✅ SMBALERT#：从机主动拉低报警线通知主机
    ARP ❌ 无 ✅ 地址解析协议：动态分配地址（多从机同一地址时用）
    典型设备 传感器、EEPROM、OLED 电池（智能电池）、PMIC、温度传感器、风扇控制器

    5.2 为什么 SMBus 要这些「规矩」

    • 超时（25ms）：I2C 允许从机无限拖时间（时钟拉伸），这在系统管理总线上是危险的——一个卡死的从机能把整条总线拖死。SMBus 规定任何操作必须在 25ms 内完成，超时即报错，保证「坏设备不拖垮总线」。
    • PEC：系统管理总线上的数据（电池电量、电压）错一个字节可能出大事，PEC 加一个 CRC 字节让主机能校验完整性。
    • SMBALERT#：从机发现问题（如电池过热）时主动拉低报警线，主机一收到就过来查，不用轮询。
    • ARP：多个相同地址的设备（如两块同型号电池）通过 ARP 动态分配地址，避免地址冲突。

    5.3 如何用 STM32 的硬件 I2C 跑 SMBus

    好消息：SMBus 和 I2C 在物理层完全兼容（同样的开漏、同样的两根线、同样的时序），所以 STM32 的 I2C 外设可以直接连 SMBus 从设备，只要：

    1. 速率配到 100kHz（SMBus 标准上限）；
    2. 时序满足 SMBus 的 tr/tf（上升/下降时间）要求——通常标准上拉即可；
    3. 用 I2C 寄存器级访问或 HAL 的寄存器级函数，自己实现 SMBus 的命令协议（读命令寄存器等）；
    4. SMBALERT# / ARP 是额外信号线，分别接普通 GPIO 即可（SMBALERT# 是 SMBus 设备的第 4 根线：SCL、SDA、SMBALERT#、地）。

    CubeMX 里直接选 SMBus 模式（Connectivity → I2Cx → Mode: SMBus master）就能让 HAL 按 SMBus 时序初始化，但应用层协议（命令格式、PEC）仍要自己写——HAL 只保证物理时序，不实现 SMBus 协议栈。

    SMBus 不是「I2C 换个名字」

    物理兼容不等于协议兼容。I2C 里你爱怎么发就怎么发；SMBus 要求先发命令寄存器地址、再发数据的固定格式，且要遵守超时。直接用裸 I2C 去读 SMBus 设备，地址、时序对了，但命令格式不对会读不到正确数据。

    六、避坑备忘

    • 上拉电阻是生命线：I2C 板子没上拉 = 两根悬空线，第一件事就是量 SCL/SDA 空载是不是高电平（3.3V/5V）。模块通常自带上拉，自己画板必加上拉（4.7kΩ 是 400k 速率的常见值）。
    • 地址要区分 7 位和 8 位：很多芯片手册写 8 位地址（含 R/W 位，如 EEPROM 0xA0），HAL 的 HAL_I2C_Master_Transmit 第一个参数要传7 位地址（如 0x50）。写错地址直接 NACK（函数返回错误）。7 位 × 2 = 8 位，对应关系要分清。
    • SCL/SDA 的 GPIO 配置：开漏输出 + AF 复用 + 上拉，三样缺一不可（F4 是 GPIO_MODE_AF_OD + GPIO_PULLUP）。忘了开漏，总线会「推高」打架。
    • 硬件 I2C 阻塞调用别进中断：HAL_I2C_Master_Transmit 在中断里用会死锁（内部等 SysTick/HAL_Delay）。中断里用 _IT 或 _DMA 版本，或只置标志。
    • DMA 缓冲要常驻：局部变量被 DMA 异步搬运 = 悬空指针崩溃。用 static/全局/队列缓冲。
    • BUSY 标志卡死：传输被打断后外设 BUSY 不释放，再发就报忙。HAL_I2C_DeInit + HAL_I2C_Init 复位外设即可。
    • 从机地址别配错位：做从机时 OwnAddress 是 7 位；主模式发起时地址也要 7 位，别把手册的 8 位直接抄进来。
    • SMBus 设备当 I2C 用要看时序：速率别超 100k，注意从机的 25ms 超时限制，慢速轮询别被 SMBus 从机踢掉。
